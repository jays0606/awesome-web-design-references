# Reference-led design

Read [the catalog](references/catalog.json) and select entries relevant to the audience,
content, primary action, and existing brand. Inspect the selected screenshots using
available image or browser tools. Read at most the small subset needed for the task.

The catalog is bundled. Screenshot URLs point to the public repository and require
network access; local screenshot paths are relative to the repository root when the
whole repository is available. If images cannot be accessed, explain that limitation
and use the written observations without claiming visual inspection.

Choose one primary reference. Add a secondary only for a separate need. State the
specific principle being adapted and the reason it fits. A screenshot's source date,
viewport, locale, capture limitations, and review status qualify every inference.

Translate visual hierarchy, spacing, typography relationships, image proportions,
and section composition into the user's existing project. Use their content and
assets. Do not copy brand identities, copyrighted page artwork, or marketing claims.
Do not combine every reference, install a framework from its appearance, or assume
a still image proves mobile behavior, motion quality, accessibility, or performance.

For an implementation request, move from a brief rationale into a working result.
Make routine decisions without approval loops; ask only for genuinely consequential
missing information. For an exploration-only request, present distinct options and
stop before implementation. Preserve explicit user directions and design-system rules.

Validate the actual page at the requested desktop and mobile sizes. Check the primary
interaction, text overflow, keyboard focus, and reduced motion when relevant. Report
observed results separately from untested assumptions. This skill contains no scripts,
hooks, credentials, telemetry, or automatic external uploads.
